# W1 wiring: accounts and saved items in `src/server/analysFn.ts`

For the supervisor. W1 delivers implementations and tests; this file is the exact wiring for
`analysFn.ts` (which W1 does not edit). Nothing here may add a module-scope value to
`analysFn.ts`: every helper below is a function, and server-only modules are only touched
inside handlers or helper functions.

## 1. Replace `kontextFor` so every handler sees the session

```ts
import { kontextMedSession, skapaKontoBeroenden } from "./auth";

function kontextFor(env: Env): Promise<Kontext> {
  return kontextMedSession(env); // identical to before when PROJECT_PUBLISHABLE_KEY is unset
}
```

`anropareFor` keeps using `kontextFor`. A logged-in request then carries `principalId` =
the account principal, so `medPrincipal` (uploads) attributes to the account. Without the
publishable key nothing changes for anonymous users.

## 2. New helpers (functions, not values)

```ts
import {
  begarAterstallning, bekraftaEpost, hamtaSession, loggaIn, loggaUt, raderaKonto,
  registreraKonto, sattNyttLosenord,
} from "./auth";
import {
  hamtaMinaUppgifter, hamtaSparadKalkyl, hamtaSparadVardering, listaSparat,
  raderaSparadKalkyl, raderaSparadVardering, sparaKalkyl, sparaVardering,
  taBortAnalysFranLista, type SparatBeroenden,
} from "./sparat";

/** Session + store for a saved-item handler. Needs the publishable key. */
async function sparatFor(env: Env): Promise<SparatBeroenden> {
  const b = await skapaKontoBeroenden(env);
  return { kontext: b.kontext, db: b.db };
}
```

`kalkylBeroenden()` is W6's: `{ beraknaSammanfattning: (u: KalkylUnderlag) => KalkylSammanfattning, regelversion: string }`
(import it from `@/lib/kalkyl/...` once W6 has merged; a function call inside the handler, not a
module-level constant).

## 3. The server functions

All use the existing pattern: `try { … } catch (fel) { throw sakertFel("<namn>", fel); }`.
Account failures are **returned** (`{ ok: false, felKod, meddelande }`), only unexpected ones throw.
`POST` for everything that sets cookies or writes; `GET` only for pure reads.

## 4. Types the frontend consumes

All in **`src/lib/kontoTyper.ts`** (client-safe, type-only plus two constants). Every account
function returns `KontoSvar<T> = ({ ok: true } & T) | { ok: false; felKod; meddelande }`:

| Function | Return type |
|---|---|
| `hamtaSessionFn` | `SessionSvar` = `{ inloggad: false } \| { inloggad: true; epost; principalId }` |
| `registreraKontoFn` | `RegistreraKontoSvar` (`{ ok: true }`, never says whether the address exists) |
| `loggaInFn` | `LoggaInSvar` = ok + `{ epost, principalId }` |
| `loggaUtFn` | `LoggaUtSvar` |
| `begarAterstallningFn` | `BegarAterstallningSvar` (`{ ok: true }` unless rate-limited) |
| `bekraftaEpostFn` | `BekraftaEpostSvar` = ok + `{ typ, epost, principalId }`; `typ === 'recovery'` → go to `/konto/nytt-losenord` |
| `sattNyttLosenordFn` | `SattNyttLosenordSvar` |
| `sparaVarderingFn` | `SparaVarderingSvar` = ok + `{ vardering: SparadVardering }` |
| `listaSparatFn` | `ListaSparatSvar` = ok + `{ analyser: AnalysPost[]; varderingar: SparadVarderingPost[]; kalkyler: SparadKalkylPost[] }` |
| `hamtaSparadVarderingFn` | `HamtaSparadVarderingSvar` = ok + `{ vardering: SparadVardering }` (`resultat` null if the stored snapshot no longer parses; `input` allows "Räkna om") |
| `raderaSparadVarderingFn` | `RaderaSparatSvar` |
| `sparaKalkylFn` | `SparaKalkylSvar` = ok + `{ kalkyl: SparadKalkyl }` (pass `id` to update) |
| `hamtaSparadKalkylFn` | `HamtaSparadKalkylSvar` (`kalkyl.underlag` null = unknown version: show empty calculator + notice) |
| `raderaSparadKalkylFn` | `RaderaSparatSvar` |
| `taBortAnalysFranListaFn` | `TaBortAnalysFranListaSvar` (the report stays in the register) |
| `hamtaMinaUppgifterFn` | `HamtaMinaUppgifterSvar` = ok + `{ uppgifter: MinaUppgifter }` (download as JSON) |
| `raderaKontoFn` | `RaderaKontoSvar` |

`KontoFelKod`: `ogiltig_epost | svagt_losenord | ogiltig_inloggning | epost_ej_bekraftad |
ogiltig_lank | kvot | ej_inloggad | hittades_inte | ogiltig_indata | for_manga_sparade |
konto_ej_konfigurerat | unknown`. Show `meddelande` verbatim (Swedish, from `fel.ts`).
`ej_inloggad` → redirect to `/konto/logga-in?till=…`. `hittades_inte` → "hittades inte" page.

## 5. Notes for the frontend (W2)

- **The email link must not verify on a plain GET.** Mail scanners (Outlook Safelinks etc.) open
  links and would burn the one-time token. `/konto/bekrafta` should call `bekraftaEpostFn` from
  client-side code after hydration (or behind a button), not from a server loader.
- The recovery link logs the user in (session cookies set) and the page then asks for a new
  password with `sattNyttLosenordFn`. Any logged-in session can call `sattNyttLosenordFn`
  (no old password required): Supabase's `secure_password_change` is off. Flag for the owner if a
  stricter flow is wanted.
- A `kvot` result has a fixed text: "För många försök, vänta en stund."
- Cookies: `binfo_sa` (access, ~1 h) and `binfo_sr` (refresh, 30 days, sliding), httpOnly.
  The browser never sees tokens; `hamtaSessionFn` is how the client learns who is logged in.
- `SparadVarderingPost.input/…` and `SparadKalkyl.underlag` can be `null` when a stored object no
  longer parses with the current schema; render a "kan inte öppnas" state, never crash.

## 6. Behaviours to know when integrating

- After logout the device still maps to the account principal for **new anonymous uploads**
  (`sakerstall_principal` follows the merge, existing v2 behaviour). Those analyses appear in the
  account's list the next time it is opened. See open issues in the W1 report.
- `skapaKontoBeroenden` throws `KontoEjKonfigureratError` (Swedish message, passes `sakertFel`) when
  `PROJECT_PUBLISHABLE_KEY` is unset; `kontextMedSession` silently falls back to anonymous.
- `PROJECT_PUBLISHABLE_KEY` must therefore be set in Lovable Secrets for production.
